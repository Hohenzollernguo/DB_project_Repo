2026-11-10。根据已给出的官方站点 CSV，在答辩前生成持久化 JSON。每对可达起终点只保存一条最优路线，方向分别计算。同站查询返回零段路线，不写入缓存。不可达组合不写入缓存。

## Java 查询与数据库对接

首次普通路径查询流式解析 JSON，验证版本、路线选择规则、字段、站点、运营连接、路段统计、起终点唯一性和全部可达组合覆盖。站点和线路字符串复用字典，索引成功建立后供同一 Service 实例重复查询。加载失败时不发布部分结果，后续请求可以重试。

2026-11-10 老师明确允许路径功能始终按固定数据的缓存查询，前面的 CRUD 操作不影响路线结果。`findRoute` 和 `findBestRoute` 始终查询已生成的最优路线索引。

Service 使用数据库读取站点与线路的身份映射，按中文站名和行政区对应起终点 ID。返回路线的站序、换乘、名称、英文名和运营状态取固定缓存及其原始 CSV。不同数据库 ID 或重新导入仍可通过业务键对应。途经站或线路已被删除时，仍按缓存展示，DTO 中的 ID 为 0 表示当前数据库中已不存在的展示对象，该 ID 不可用于 CRUD。起终点选择继续使用现有车站查询接口。

路径查询的在线调用只读取身份映射和内存缓存。Dijkstra 用于离线生成 JSON。运营状态、站线移除、删除途经站、删除线路或新增捷径均保持已缓存的路线结果。

输入无效返回 `INVALID_INPUT`，站点不存在返回 `NOT_FOUND`，存在但不可达返回 `NO_ROUTE`。同站查询返回包含该站的零段路线。缓存缺失、损坏或版本不匹配返回 `DB_ERROR` 并提示检查或重新生成。

默认支持从 Task4、仓库根目录或外层工作区启动，使用 `Task4/cache/routes-cache.json` 及对应官方 CSV。其他工作目录可通过 JVM 参数 `-Dmetro.routeCache=<JSON路径>` 和 `-Dmetro.routeSource=<CSV路径>` 显式指定。依赖由 Maven 管理，IDEA/Maven 启动时会带上 Jackson Core 和 pgJDBC。

JSON 使用 Jackson Core 的流式解析接口读取。[官方 API](https://www.javadoc.io/static/com.fasterxml.jackson.core/jackson-core/2.20.2/com/fasterxml/jackson/core/JsonFactory.html)

## 数据和路线规则

- 原始文件为 `官方描述及数据/shenzhen_stations.csv`。使用与 Task3 导入器相同的字段和 trim 规则，按 `Num` 构建完整站序。生成器校验站序连续、同线路站点唯一和线路中英文名称对应关系。
- 站点业务键为中文站名和行政区。缓存中的 `line` 为完整中文线路名称，保留分期信息。状态内部索引独立于数据库 ID。
- 状态为站点与线路的组合。相邻且两端均 Operation 的站线关系建立双向乘车边，代价为 `(1, 0)`。同站各运营线路之间建立换乘边，代价为 `(0, 1)`。
- 在完整站序上判断邻接，在建站会阻断连接。线路首尾、不同分期和不同站点业务键之间不会自动补边。
- 每个起点运行一次 Dijkstra，起点各条运营线路均以零代价入队，第一次上车不计换乘。
- 优先比较最少站间段，再比较最少换乘。仍相同时，比较完整状态序列的业务键字典序，每个状态依次比较中文站名、行政区和完整中文线路名，使用 Java `String.compareTo`，换乘站在序列中保留换乘前后的两个状态。输入记录顺序不会影响结果。
- 完整状态路径按连续线路合并为 `legs`，相邻路段共享换乘站。每条路线的 `stopCount` 是各路段站点数减一之和，`transferCount` 是路段数减一。

## JSON 格式

顶层保留 `formatVersion`、`routingRule`、`routes`。每条路线保留 `from`、`to`、`stopCount`、`transferCount`、`legs`，每个站点是 `name` 和 `district` 对象，每段包含 `line` 和 `stations`。

文件是一个完整的 JSON 对象。每条路线占一行，减少格式空白并支持低内存逐条验证。每条记录只含最终最优路线，不含搜索过程或备选路径。

原始数据中存在但缓存没有对应记录的不同站点组合，表示在当前规则下不可达。接入查询时先检查站点是否存在，再区分同站零段查询与不可达结果。

## 验证
