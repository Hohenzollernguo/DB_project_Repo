# 插入车站复用已有资料

GUI 原先在插入任何车站时都展示空白站线属性表单，导致已有车站的开通年份、首末班时间、状态和坐标需要重复填写。

## 交互

在“站线管理”选择目标线路，点击“插入车站”，通过候选或“选择车站”选定车站后，表单异步读取该车站已有的站线资料并自动填入。用户只需确认目标站序，已有资料无需重填。

同一换乘站在不同线路上的开通年份、首末班时间等可能不同。表单默认优先选择运营中的来源，其次按开通年份、线路内部 ID 升序选择；“已有资料来源”显示完整线路名称和 ID，可切换来源。每次使用一条完整记录，不将不同线路的字段混合。自动填入的值允许调整为目标线路的资料。

车站本身只存中英文名和行政区。若车站没有任何站线关系，例如刚创建的新站，数据库中没有可复用的年份或时间，此时清空表单并提示补填。年份和状态仍按原规则必填，时间、坐标可空，不猜测缺失年份。

选择或切换车站会清空上一站资料。读取完成前、查询失败或未选中车站时，不能提交插入。旧请求即使较晚返回，也不会覆盖新选择的资料。关闭或取消表单不会写入数据库。格式错误会在当前对话框中提示，保留已填写内容供修改。

## 接口与数据

本说明作为原 JDBC 开发约定的接口增补：

- `LineService.getStopSources(long stationId)` 返回 `List<StopSource>`；非正 ID 返回 `INVALID_INPUT`，没有来源时返回空列表。
- `StopSource(LineView line, StopDraft attributes)` 保存来源线路和该来源的全部站线属性。现有 record 构造参数不变。
- `JdbcLineService` 使用只读快照事务调用 `LineStationDao.findSourcesByStation`，按车站 ID 查询 `line_station` 并关联 `metro_line`。
- `StopInsertPanel` 在 `SwingWorker` 中读取，完成后在 EDT 更新表单；提交仍调用现有 `insertStops`，复用站序连续性、重复车站、属性校验和回滚逻辑。

表结构、Task3 导入 SQL 和 Q7 无需变更。读取和填入只复制属性，不修改来源线路上的数据；用户确认插入后才写入目标线路的新站线关系。

## 检查范围

- `StopInsertPanelTest`：已有资料自动填入、允许调整、切换换乘来源、可空值清空、无资料补填、异步读取、旧请求返回、清除选择与查询失败时禁止提交。
- `JdbcGetStopsTest`：无效车站 ID 在访问数据库前拒绝。
- `StopInsertPostgresTest`：通过实际表单读取真实 PostgreSQL 资料，无需重填即可插入指定站序，后续站点顺延，来源线路不变；换乘来源属性保持分离；无来源车站补填年份后插入。
