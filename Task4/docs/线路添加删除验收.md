# 线路添加和删除验收

初次验收日期为 2026-11-07。实现覆盖 `LineService.create(LineDraft)` 和 `LineService.delete(long)`，并接入 CLI 与 Swing。2026-11-09 调整删除交互，以下删除入口说明采用新的编号查询与候选选择流程。

## 实现与入口

| 功能 | 数据库与业务行为 | CLI | Swing |
|---|---|---|---|
| 添加线路 | 参数化 INSERT RETURNING，由数据库分配 ID，返回完整 LineView，允许新建空线路 | 菜单 9，填写中英文名 | 添加线路按钮 |
| 修改名称 | 按编号查询并选定线路，使用实际 ID 同时更新中英文名，返回原 ID 和新名称 | 菜单 2，输入编号，多条时选择候选 ID | 修改线路名称按钮，先按编号查询并选择 |
| 删除线路 | 用户按编号查询并选定线路，程序取得实际 line_id 执行 DELETE，外键限制拒绝删除仍关联站点的线路 | 菜单 10，输入编号，多条时选择候选 ID，再输入 YES 确认 | 输入编号并查询，多条时选择显示 ID 和名称的候选，再勾选确认并删除 |

名称规范化沿用现有 Service 规则，去除首尾空白，拒绝 null、空白或包含空字符的名称。中英文名各自的唯一冲突返回 DUPLICATE。删除时，非法 ID 返回 INVALID_INPUT，目标不存在返回 NOT_FOUND，线路仍被使用返回 IN_USE。

添加通过 Transactions.write 执行，删除通过 Transactions.delete 执行。异常由既有事务层回滚和转换错误码。Swing 使用后台线程查询和提交，执行期间禁用输入和重复提交，完成后恢复操作。删除表单编辑线路编号时清空候选与确认，切换候选时也会清除确认。

主要代码位于 LineDao、JdbcLineService、CliApp、DesktopApp、LineCreatePanel 和 LineDeletePanel。AppBootstrap 继续提供双方界面共用的 LineService 实例。

## 按编号删除的交互规则

用户输入线路名称中的编号，例如 `13`。编号去除首尾空白后必须是正整数字符串，按查询合同匹配该编号的全部记录。输入 `1` 只得到编号为 1 的线路。

1. 没有匹配时显示未找到线路，结束本次删除。
2. 只有一条匹配时自动选中该条记录，并显示其实际 ID 与中英文名。
3. 多条匹配时列出每条线路的实际 ID 与中英文名。CLI 仅接受候选中的 ID，空行取消选择。Swing 候选列表初始不选中任何项，用户按显示的 ID 选择具体线路。
4. 选定线路后再明确确认。CLI 输入 `YES`，其他输入取消。Swing 勾选确认后点击删除。输入结束或非法选择均不会执行删除。
5. 程序将选中记录的 `lineId` 传给 `LineService.delete(long)`。例如编号 `13` 查得 `Line 13` 的内部 ID 为 `42`，最终执行 `delete(42)`。一次操作只删除选中的一条记录。

Service 与 DAO 继续按内部 `line_id` 定位，删除目标在查询后已被其他请求删除时返回 `NOT_FOUND`，仍关联站点时返回 `IN_USE`。用户首次输入的编号与候选选择阶段的 ID 分别由提示明确说明。

删除交互测试覆盖编号与内部 ID 不同、同编号多候选、无匹配、非法编号、非法或候选外 ID、空行取消、确认取消、输入结束，以及 Swing 的异步执行、重复提交保护与目标变化后清除旧选择。

## 复现

在 Task4 目录，使用个人终端或 IDEA 配置测试环境变量后执行下列命令。

```powershell
$env:METRO_TEST_DB_URL = 'jdbc:postgresql://localhost:5432/postgres'
$env:METRO_TEST_DB_USER = 'your_test_user'
$env:METRO_TEST_DB_PASSWORD = 'your_local_password'
.\scripts\mvn-local.ps1 -Goals verify
```

测试账号需要创建和删除数据库的权限。四个实库测试类共用 PostgresTestDatabase，每类创建随机命名的 metro_line_test_<uuid> 数据库，在其中加载共享 `Task3/tools/create_table.sql` 并准备测试数据，结束时删除自身创建的数据库。该 DDL 路径已按远端 Task3 整理结果统一。程序正常启动继续读取 DB_URL、DB_USER 和 DB_PASSWORD 环境变量。

本次环境为 PostgreSQL 12.1、JDK 21.0.10，Java 编译目标为 17。团队 PostgreSQL 16 和独立 JDK 17 的环境验收尚待执行。
